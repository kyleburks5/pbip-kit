## Releases

The kit is versioned `MAJOR.MINOR.PATCH` (git tag `v<version>`; pbik has its own version in `pbikit/__init__.py`,
same rules):

- **patch**: fixes, docs, lessons, a refreshed catalog, templates or schema-support.json. A rep's layout.json builds
  the same report, apart from the fix.
- **minor**: something new that leaves existing reps alone: a layout key, a pbik command or option, a command, a
  pattern, a validate warning. Rebuilding an existing rep gives the same files, or only the new thing.
- **major**: something that breaks an existing rep: a layout key renamed or removed, a different output for the same
  layout.json (rebuild with `--reset`), a new validate error on files that passed, or a workflow step removed.

Each release names the Power BI Desktop version it was tested on: a /smoke, or the Desktop check named in the
changelog. "Not Desktop-tested" means the tests and the regression suite only.

## How the pinning is set

- `~/.claude/plugins/known_marketplaces.json`: `"autoUpdate": false` on all three marketplaces (checked 2026-10-17).
- `~/.claude/settings.json`: the `FORCE_AUTOUPDATE_PLUGINS` environment variable removed.
- To update on purpose: `/plugin` in a `claude` terminal, update one marketplace, then run `/smoke` and record it here.

## Update policy

- Freeze versions during a rep. Don't update anything until the rep is committed.
- Between reps, update one component at a time.
- After a Power BI Desktop update, run `/update` (docs/UPDATE-ROUTINE.md): record the version, regression suite, /smoke, then new visuals or settings through the Patterns page, harvest and catalog refresh.
- After any update, run `/smoke`: build one card, one button slicer and one table, reload in Desktop, and check them against `design/checks.md`. Record the new version here.
